# Security audit, 22 November 2026

Scope: ELEPAY-Core application code, configuration and migrations on `feature/modular-monolith`. Method: review of
authentication, authorization, secrets, cryptography, card data handling, outbound calls, SQL, logging and
integrity controls, with tests added for every fix. Not in scope: infrastructure, cloud IAM, network, the web
app's hosting, third-party penetration testing.

## Fixed

| # | Severity | Finding | Fix | PCI DSS v4.0.1 |
|---|---|---|---|---|
| 1 | Critical | Simulated rail enabled by default (`ELEPAY_SANDBOX_ENABLED` defaulted to `true`), so production could accept simulated money | Default `false`; only dev, sandbox and test profiles enable it; production refuses to start with it on | 6.5.3 |
| 2 | Critical | Request-signing secret had a public default (`elepay-default-signing-secret-key-32b`) | No default; a signed request without a configured secret is refused (`signing_not_configured`) | 8.3.2, 8.6.2 |
| 3 | Critical | Card numbers encrypted with a public default key, built from text bytes rather than random key material | Base64 256-bit key required (`ELEPAY_VAULT_MASTER_KEY`), no default; ciphertext versioned (`v2:`, with AAD); old rows re-encrypted at start-up | 3.5.1, 3.6.1, 3.7 |
| 4 | Critical | Any signed-in user or API key could read or revoke any card token (`GET/DELETE /v1/rails/card/tokens/{token}`) | Tokens record their owner; only the owner or operations can read or revoke; others get 404 | 7.2.1, 7.2.2 |
| 5 | High | Card fingerprints were an unkeyed SHA-256 of the card number, which can be brute-forced back to the PAN | HMAC-SHA256 under a key derived from the vault key; existing fingerprints recomputed | 3.5.1.1 |
| 6 | High | Webhook SSRF: merchants could make ELEPAY call any URL, including cloud metadata, the management port and Redis | `OutboundUrlGuard`: https only, public addresses only, ports 443 and 8443; checked at registration and before every delivery; redirects not followed | 1.4, 6.2.4 |
| 7 | Medium | Prometheus metrics public on the main port | Served only on the internal management port; otherwise ops role required | 7.2.1 |
| 8 | Medium | Step-up OTP and gift-card PIN hashes compared in non-constant time | `MessageDigest.isEqual` | 6.2.4 |
| 9 | Medium | Balance snapshots could fail verification (or verify wrongly) under concurrent postings: the cut-off used transaction start time | Journal entries get an insert-ordered `entry_seq`; snapshots store an exact cut-off; signed timestamp matches the stored one | 10.3, 10.7 |
| 10 | Low | Grafana admin password `admin` in the monitoring compose file | Must be set via `GRAFANA_ADMIN_PASSWORD` | 2.2.2 |

`ProductionSafetyCheck` makes the `prod` profile refuse to start with any of 1, 2, 3 or 6 misconfigured, with dev
tokens configured, without an OIDC issuer, or with any secret that has appeared in this repository.

## Open

| # | Severity | Finding | Plan |
|---|---|---|---|
| 11 | High | Audit-log hash chain and snapshot "signatures" use unkeyed SHA-256: anyone with database write access can rewrite and re-chain them | Keyed integrity (HMAC-SHA-512) plus ML-DSA signed checkpoints, versioned; part of the post-quantum work |
| 12 | Medium | Fraud and AML/sanctions engines are not called when money moves | Wiring into transfers, checkout payments and payouts (planned) |
| 13 | Medium | Webhook DNS rebinding: the address is checked before the call, but the HTTP client resolves again | Pin the checked address on the connection, or deliver through an egress proxy that enforces the same policy |
| 14 | Medium | No dependency vulnerability scanning in CI | Add OWASP Dependency-Check or GitHub Dependabot with a fail threshold |
| 15 | Low | Request signing is optional (`ELEPAY_ENFORCE_REQUEST_SIGNING=false`) | Decide per client type; enforce for server-to-server API keys |

## Production configuration now required

| Variable | Value |
|---|---|
| `ELEPAY_VAULT_MASTER_KEY` | `openssl rand -base64 32`, from a secrets manager or KMS. Keep it: it decrypts stored cards |
| `ELEPAY_OIDC_ISSUER` | The identity provider issuer URL |
| `ELEPAY_SIGNING_SECRET` | Optional; if set, at least 32 random characters |
| `ELEPAY_SANDBOX_ENABLED` | Unset or `false` |
| `elepay.vault.legacy-master-key` | Only if earlier releases ran with a custom `elepay.vault.master-key`: that value, so old cards can be upgraded. Remove after start-up logs report the upgrade |
